## Reversible Asset Workflow

1. Use a dedicated asset-only branch.
2. Replace only files listed in the deferred asset map.
3. Prefer regenerating from the design/source-of-truth file instead of editing
   screenshots in place.
4. Keep filenames and dimensions unchanged unless design explicitly approves a
   change.
5. Produce before/after contact sheets for every changed asset.
6. Run `git diff --stat` and confirm no unrelated binary assets changed.
7. Capture at least one current-source onboarding GUI screenshot after asset
   replacement if the machine is cool and GUI prerequisites are safe.
8. Update the GUI matrix and release-candidate record with `visual-regenerated`,
   `design-approved`, or `still-visual-residue`.
